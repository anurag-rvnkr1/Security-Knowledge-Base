# Markdown Style Guide

- Use one `#` title per file, followed by ordered `##` and `###` sections.
- Prefer concise paragraphs and parallel list items.
- Use tables for compact structured comparisons and include meaningful column headings.
- Fence code and queries with a language identifier, for example `bash`, `powershell`, `kusto`, `yaml`, or `text`.
- Use inline code for commands, paths, fields, and identifiers.
- Use relative Markdown links for repository files; encode spaces as `%20` where needed.
- Provide useful alt text for images and include attribution where required.
- Use blockquotes for short summaries or cautions; do not rely on color alone.
- Identify assumptions, platform/version dependencies, risk, and expected output.
- Check that code fences, tables, headings, and links render correctly before submission.
