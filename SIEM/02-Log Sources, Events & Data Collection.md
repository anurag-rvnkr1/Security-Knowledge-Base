# Chapter 02 – Log Sources, Events & Data Collection

> A SIEM can only detect what it can observe. Understanding where security telemetry originates, what information it contains, how it is collected, and what data is worth ingesting is fundamental to effective security monitoring.

---

# 1. Introduction

Every SIEM begins with data.

```text
Systems
   ↓
Generate Events
   ↓
Events Become Logs / Telemetry
   ↓
Collected
   ↓
Sent to SIEM
   ↓
Parsed / Normalized
   ↓
Analyzed
```

A SIEM does not magically create visibility.

If an organization does not collect authentication logs, endpoint telemetry, network events, or cloud audit logs, the SIEM cannot reliably analyze activity that those logs would have revealed.

Therefore:

> **Visibility is the foundation of detection.**

---

# 3. What is Security Telemetry?

**Security telemetry** is data generated by systems and security controls that can provide visibility into security-relevant activity.

It can include:

```text
Logs
Events
Network Flows
Process Information
Authentication Events
Endpoint Telemetry
Cloud Audit Events
DNS Queries
Threat Intelligence
Security Alerts
```

Telemetry is broader than traditional text logs.

---

# 4. Event vs Log vs Telemetry

These terms are related but should not be treated as identical.

### Event

Something that happened.

```text
User authentication failed.
```

### Log

A recorded representation of an event.

```text
2026-08-13 10:20:15
user=alice
action=login
status=failed
```

### Telemetry

Broader security-relevant information.

```text
Process
Network Connection
Authentication
DNS Query
File Event
Cloud API Call
```

Simplified:

```text
EVENT
 ↓
Something happened

LOG
 ↓
Recorded event

TELEMETRY
 ↓
Security-relevant observable data
```

# 5. Why Log Sources Matter

Consider an account compromise.

The attacker may generate:

```text
Failed Logins
Successful Login
MFA Event
New Device
New IP
Privilege Change
Cloud API Activity
Data Access
```

If the SIEM only receives:

```text
Firewall Logs
```

the organization may miss important identity and endpoint evidence.

If it receives:

```text
Identity
+
Endpoint
+
Network
+
Cloud
```

the analyst can reconstruct a much more complete attack timeline.

# 102. Interview Questions

### What is a log source?

> A system, application, device, or security control that generates telemetry consumed by a SIEM.

### What is security telemetry?

> Security-relevant observable data such as logs, events, network flows, process activity, and cloud audit records.

### What are common SIEM log sources?

> Endpoints, identity systems, firewalls, DNS, VPN, IDS/IPS, EDR, applications, databases, cloud platforms, and security tools.

### Why are authentication logs important?

> They provide visibility into account access, failures, unusual locations, privilege use, and potential account compromise.

### Why are DNS logs useful?

> They can reveal suspicious domains, malware command-and-control, tunneling, and unusual DNS behavior.

### Why are endpoint logs important?

> They provide visibility into processes, files, commands, network connections, and other activity occurring on hosts.

### What is Sysmon?

> A Windows system activity monitoring tool that provides detailed telemetry useful for security monitoring.

### What is log parsing?

> Extracting meaningful fields from raw log data.

### What is normalization?

> Converting different source-specific fields and formats into a consistent schema.

### What is log enrichment?

> Adding additional contextual information such as threat intelligence, asset criticality, or user information.

### Why is timestamp accuracy important?

> Accurate timestamps are essential for event correlation and reconstructing incident timelines.

### What happens if a log source stops sending?

> The SIEM may lose visibility and detections depending on that source, so log-source health monitoring is essential.

### Should all logs be sent to a SIEM?

> Not necessarily. Organizations should prioritize security-relevant telemetry while balancing detection value, cost, storage, and privacy requirements.

### What is log flooding?

> Generating excessive log volume that can overwhelm collectors, processing systems, storage, or analysts.
